How I Connected My System to a Cloud Database

A step-by-step guide using CareConnect (a Barangay Health Center information system built with React + Vite) and Supabase (a cloud PostgreSQL database with built-in authentication).

Overview — how the pieces connect

The website and the database are two separate things. The website (the React app) runs in the browser. The database lives in the cloud. The Supabase JavaScript library is the bridge: it sends requests over HTTPS to the project's URL, using a public API key, and the database decides what each logged-in user is allowed to see.

Key idea"localhost" is only where the website runs. The data is stored online in Supabase, so it stays even when the computer is turned off.

What you need first

  • A free account at supabase.com (sign in with GitHub or e-mail).
  • Node.js 18 or newer, and a code editor (VS Code).
  • A React + Vite project. Mine was created with npm create vite@latest careconnect -- --template react.

The steps

  1. Create the Supabase project

    In the Supabase dashboard click New project. Give it a name (mine: careconnect-db), set a strong database password (save it somewhere safe), choose the region closest to the users (e.g. Southeast Asia / Singapore), and press Create. Wait about two minutes until the project says it is ready.

  2. Copy the API credentials

    Open Project Settings → API (or the Connect button at the top). You need only two values:

    ValueLooks likeUse it in the website?
    Project URLhttps://abcdxyz.supabase.coYes
    anon / public keyeyJhbGciOi… (long token)Yes — it is safe to ship because Row Level Security protects the data
    service_role keyeyJhbGciOi…NEVER. It bypasses all security. Server only.

  3. Install the Supabase client library

    In the project folder, open a terminal:

    npm install @supabase/supabase-js

  4. Store the credentials in a .env file

    Create a file named .env in the root of the project (next to package.json, not inside src):

    VITE_SUPABASE_URL=https://YOUR-PROJECT-ID.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR-ANON-PUBLIC-KEY
    Two common mistakesVite only exposes variables that start with VITE_. And after editing .env you must stop and restart npm run dev — it is read only at startup.

    Add .env to .gitignore so the keys are not pushed to GitHub.

  5. Create the Supabase client (one file used everywhere)

    src/lib/supabase.js

    import { createClient } from '@supabase/supabase-js';

const url = import.meta.env.VITE_SUPABASE_URL;
const key = import.meta.env.VITE_SUPABASE_ANON_KEY;

export const isConfigured = Boolean(url && key);

export const supabase = createClient(url, key, {
  auth: { storage: window.sessionStorage, persistSession: true, autoRefreshToken: true },
});

    Every component simply does import { supabase } from '../lib/supabase'. In CareConnect the login is kept in sessionStorage, so closing the browser logs the user out.

  6. Create the tables with the SQL Editor

    In Supabase open SQL Editor → New query, paste the schema, and press Run. A short excerpt from CareConnect's schema.sql:

    create table public.profiles (
  id          uuid primary key references auth.users(id) on delete cascade,
  first_name  text not null,
  last_name   text not null,
  role        text not null default 'resident'
              check (role in ('resident','bhw','admin'))
);

create table public.patients (
  id          uuid primary key default gen_random_uuid(),
  profile_id  uuid unique references public.profiles(id),
  first_name  text not null,
  last_name   text not null,
  birth_date  date,
  purok       text
);

-- turn Row Level Security ON and add rules
alter table public.patients enable row level security;

create policy patients_select on public.patients for select
  using (profile_id = auth.uid() or public.is_staff());
    Why RLS?The browser talks to the database directly, so the rules about who may read or write which row must live in the database. That is what Row Level Security does (see Lab 2 — authorization).

  7. Test the connection

    Temporarily add this to any component (for example App.jsx) and look at the browser console (F12):

    import { useEffect } from 'react';
import { supabase } from './lib/supabase';

useEffect(() => {
  supabase.from('public_medicine_stock').select('*').limit(3)
    .then(({ data, error }) => console.log('data:', data, 'error:', error));
}, []);
    • data is an array and error is null → connected ✔
    • In the Network tab you will see a request to …supabase.co/rest/v1/… with status 200.

    You can also confirm in the dashboard: Table Editor shows the same rows that your app received.

  8. Connect login (Supabase Auth)

    // Sign up (creates a row in auth.users)
await supabase.auth.signUp({
  email, password,
  options: { data: { first_name, last_name } }
});

// Sign in
const { data, error } = await supabase.auth.signInWithPassword({ email, password });

// Who is logged in? / Sign out
const { data: { session } } = await supabase.auth.getSession();
await supabase.auth.signOut();

    A database trigger (handle_new_user) automatically creates the matching profiles row whenever a new auth user appears, so every account has a role.

  9. Read and write data from React (CRUD)

    // CREATE
await supabase.from('queue').insert({ patient_id, reason: 'Fever' });

// READ (with a related table)
const { data } = await supabase
  .from('queue')
  .select('id, status, patient:patients(first_name, last_name)')
  .in('status', ['waiting', 'in_consultation'])
  .order('created_at');

// UPDATE
await supabase.from('queue').update({ status: 'done' }).eq('id', id);

// DELETE
await supabase.from('events').delete().eq('id', id);

// REALTIME — refresh the screen when someone else changes the queue
supabase.channel('queue-live')
  .on('postgres_changes', { event: '*', schema: 'public', table: 'queue' }, load)
  .subscribe();

    Every call returns { data, error }. Always check error first.

Security checklist

  • Only the anon key is in the website. The service_role key and the database password are never in code or GitHub.
  • Row Level Security is enabled on every table, with a policy for each action.
  • .env is listed in .gitignore.
  • Private files (lab result photos) go in a private Storage bucket, opened with short-lived signed links.
  • When the site is deployed, add its address under Authentication → URL Configuration → Site URL.

Summary

Create project → copy URL + anon key → npm install @supabase/supabase-js → put keys in .env → create one shared client → run the SQL schema with RLS → test with a simple select → add Auth → use insert / select / update / delete from React. The database stays in the cloud; only the website runs locally until it is deployed.
