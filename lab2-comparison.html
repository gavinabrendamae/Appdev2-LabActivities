Authentication (AuthN) vs Authorization (AuthZ)

Two words that sound alike but answer two different questions. Read the comparison, then try the two demo pages.

AuthN

Authentication

“Who are you?”

Proving that a user really is who they claim to be, usually with a password, a one-time code, a fingerprint or a security key.

Happens: first, at login.

AuthZ

Authorization

“What are you allowed to do?”

Deciding which pages, data and actions an already-identified user may use, based on role, ownership or rules.

Happens: second, on every request after login.

Side-by-side comparison

Authentication (AuthN)Authorization (AuthZ)
Question answeredWho are you?What can you do?
PurposeVerify identityGrant or deny access to resources
OrderAlways firstAfter authentication succeeds
InputCredentials: password, OTP, biometrics, tokenThe identity + its role / permissions / policies
ResultA session or token (e.g. JWT) — “this is Brenda”Allow or deny each request — “Brenda may read, may not delete”
Failure response401 Unauthorized (not logged in / bad credentials)403 Forbidden (logged in, but not permitted)
Visible to the user?Yes — the login screenMostly invisible — menus, buttons and data simply appear or not
Can the user change it?Yes — user can change their own passwordNo — set by an administrator or the system
Common techniquesPassword hashing, MFA, OAuth login, SSO, biometricsRBAC (roles), ACLs, ABAC (attributes), database Row Level Security
Example in CareConnectLogging in with e-mail + password through Supabase AuthOnly a Midwife / Admin may write a prescription; a resident sees only their own record

How they work together

Analogy-AN AIRPORT. Showing your passport at check-in is authentication(the airline now knows who you are). The boarding pass that only opens the gate to your flight is authorization (what you are allowed to do). Having a valid passport does not let you walk onto any plane.

One-line ruleAuthentication without authorization = everyone who logs in can do everything. Authorization without authentication = rules that cannot be applied, because the system does not know who is asking.
