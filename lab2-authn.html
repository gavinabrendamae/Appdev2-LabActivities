Protected resource

What this demonstrates

  • Identity claim + proof — the email says who you claim to be; the password is the proof.
  • Hashing — the server keeps only a salted hash, so a leaked database does not reveal passwords.
  • Generic error message — “Invalid email or password” never tells an attacker whether the email exists.
  • Brute-force protection — repeated failures lock the account temporarily.
  • Multi-factor — password (something you know) + code on your phone (something you have).
  • Session token — after proof, requests carry a token instead of the password. No token → 401 Unauthorized.
